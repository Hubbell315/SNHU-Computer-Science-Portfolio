That work helped me connect technical behavior to business needs. A successful API response does not automatically mean that an integration produces accurate or dependable results. Understanding the expected data, handling failures and explaining limitations are necessary parts of delivering useful software. My railroad experience also required coordination with others in situations where clear communication mattered. Together, these experiences have strengthened my appreciation for listening, confirming understanding and making decisions with the broader operation in mind. Throughout the program, I have practiced communicating through project documentation, written reflections and technical explanations. These experiences support the communication outcome by demonstrating oral, written and visual presentation adapted to the purpose of the work.

My earlier data structures and algorithms coursework developed my understanding of collections, searching, sorting and complexity analysis. The capstone helped me apply those concepts within a complete application. I implemented a custom merge sort for a typed collection of trip records, allowing users to sort matching results by price or duration. The implementation provides O(n log n) time complexity and uses O(n) auxiliary space for n matching trips. This required me to consider the memory cost alongside predictable sorting performance. I also had to evaluate where different operations belonged. Filtering trip records through the API reduces the collection returned to Angular, while sorting the returned collection onto the client allows users to change its order without another API request. Handling formatted price and duration strings required numeric parsing before comparison. These decisions demonstrated the outcome involving algorithmic principles and design trade-offs. They also showed me that choosing an algorithm is only part of solving a problem. The surrounding data representation and application behavior matter as well. My checks verified functionality with the available sample data and I would need larger data sets and performance measurements before making claims about production-scale behavior.

CS 465: Full Stack Development strengthened my understanding of how an Angular interface, an Express REST API and MongoDB work together. CS 340: Client/Server Development provided additional experience connecting database operations to a user-facing application using MongoDB and Python. These courses helped me understand that database design and application design affect each other. The structure of stored data influences validation, query behavior and what the interface can reliably display. CS 320: Software Testing, Automation and Quality Assurance strengthened my understanding of unit testing and checking behavior against requirements. That experience informs how I evaluate changes, including invalid inputs and failure conditions. For the capstone, I built the Angular application, ran the backend with MongoDB and manually checked filtering, sorting, authentication and validation behavior. These checks provided evidence for implemented functionality. Expanding automated coverage remains an area for continued improvement, particularly regression tests that confirm later changes preserve expected behavior. My database enhancement introduced integer priceCents and durationDays fields alongside the existing display strings, allowing MongoDB to perform numeric range filtering. I also added validation, a normalized resort search field, indexes and a migration script with a dry-run mode. An existing nonunique trip-code index conflicted with the new unique constraint during migration. Checking duplicate codes, correcting the index and rerunning the migration taught me to consider existing data and database state when changing a schema. These improvements demonstrate the outcome involving well-founded tools and techniques that deliver practical value: more consistent trip data, usable filtering and clearer backend behavior.

My internship and independent application work have helped extend these lessons beyond coursework. Working with APIs, automation and application persistence has reinforced the importance of understanding the complete path from input to stored data to output. I want to continue developing my skills in automated testing, system design and operating applications under real workloads. Security has had a strong influence on how I approach software development. CS 305: Software Security and CS 405: Secure Coding helped me understand vulnerability identification, input validation, encryption, dependency review and the importance of considering security throughout development. My CS 405 security policy work also strengthened my understanding of zero-trust principles and the need to justify access rather than assume that requests or inputs are safe. I applied this mindset when reviewing Travlr Getaways. The original JWT middleware could allow a request to continue before token verification had established that the token was valid. I corrected that flow and required authentication for administrative create, update and delete operations while preserving public trip browsing. I manually verified that an unauthenticated delete request returned HTTP 401 and left the trip data unchanged. I also restricted writable fields, strengthened validation and returned controlled error responses rather than exposing raw database details. These changes support the security outcome by identifying design flaws and addressing specific paths through which data could be changed without appropriate protection. They reinforced that a working login does not prove every route is secure.

Travlr Getaways is the central artifact in this capstone portfolio. Using the same application across all three categories allowed me to demonstrate how software design, algorithms and databases contribute to one computing solution. The software design and engineering enhancement improved validation, error handling, maintainability and authentication. The algorithms and data structures enhancement introduced resort filtering and custom sorting with an explicit analysis of complexity and trade-offs. The database enhancement improved data representation, constraints, migration and query functionality. Together, these changes show my ability to evaluate an existing codebase and make connected improvements while preserving its core purpose. The original artifact established the starting point, the code review explains my initial analysis and the enhanced source code provides evidence of the changes. The accompanying narratives describe my reasoning, challenges and learning. My broader coursework supplies additional examples of testing, security and client/server development. This portfolio demonstrates progress across the five outcomes - supporting collaboration, communicating technical work, evaluating algorithmic solutions, applying computing tools to deliver value and developing a security mindset. It also identifies areas where I intend to grow, including automated regression testing and performance evaluation. As I’m preparing to complete my degree in November 2026, I want to bring this combination of practical development, careful analysis and accountability to a software engineering team.
