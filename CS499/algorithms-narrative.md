The artifact selected for my algorithms and data structures enhancement is Travlr Getaways - a full-stack travel application originally developed for CS 465 in June 2026. The application uses Angular for the administrative interface, Node.js and Express for the REST API, MongoDB for persistence and JSON Web Tokens for authentication. I selected this artifact because it provides a complete application where an algorithm can solve a practical problem. In the original version, trip records were stored in a typed `Trip[]` array and displayed in the order returned by the backend. With this, users had no way to filter trips by resort or sort them by values such as price or duration. For this enhancement, I added resort-based searching and a custom merge sort that operates on the matching `Trip[]` collection. The API accepts an optional resort query and returns matching records, while the Angular interface allows users to sort those results by price or duration in ascending or descending order. I created a separate `trip-sort.ts` utility containing the merge sort, comparator logic and numeric parsing needed because the existing price and duration fields are stored as strings. I also preserved the original matching collection separately from the displayed sorted collection so users can change sorting options without making another API request.

For this, I used merge sort because it provides predictable O(m log m) time complexity for m matching trips, with O(m) additional space being used during merging. I believe this was an acceptable trade-off for the application because it provides predictable performance while clearly demonstrating the use of an algorithm beyond a built-in sorting function. The backend also reduces the data set before sorting by performing the resort filtering through the API. This enhancement meets my planned algorithms and data structures course outcome by demonstrating algorithm selection, complexity analysis, data-structure use and consideration of design trade-offs. My overall enhancement plan hasn’t changed and the database-specific improvements identified during my original code review will remain part of the next milestone.

The enhancement process helped me better understand how algorithm decisions fit into a full-stack application. One challenge was handling price and duration values that were originally stored as formatted strings, which required converting them to numeric values before they could be compared correctly. Also, I had to decide whether filtering and sorting should occur on the client or server. I chose to filter through the API to reduce the returned collection and then apply the custom merge sort in Angular. I verified this enhancement by successfully building the Angular application, running the Express backend with MongoDB, testing resort filtering and confirming that price sorting worked in both directions. Overall, the enhancement improved the usefulness of the application while giving me a clear example of applying algorithms and data structures to a practical software problem.
